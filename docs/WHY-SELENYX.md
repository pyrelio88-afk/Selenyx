# WHY-SELENYX.md — 为什么是 Selenyx，为什么是这个架构

> 读这一篇你会知道：Selenyx 是什么、为什么适合科研、为什么值得用、别人凭什么换过来。
> 不写口号，只说事实与权衡。

## 一、Selenyx 是什么（一句话）

**Selenyx 是一款开箱即用的科研助手桌面应用**——查文献、读文献、写报告、做 AIGC 率/查重/降重，
全部在本地完成，月色无声，数据有据。

不绑定学科。SBAR 交接、心力衰竭、循证护理用得到；机器学习、分子生物学、人文社科同样用得到。
Selenyx 关心的是「研究流程」本身，而不是某一类研究。

## 二、为什么这个架构适合科研

科研场景有三个特殊约束，是通用 Agent 框架做不到位的：

1. **证据链不能丢**：论文里 `[1]`、`(Smith, 2020)`、DOI、剂量单位 `5.2 mg/kg`、p 值 `p<0.01`——这些是引文与数据的生命线，翻译和改写时必须零污染。
2. **本地敏感数据**：未发表数据、知情同意书、伦理材料、原始问卷——不能上云。
3. **长链路人机协作**：研究不是"一气呵成"，而是有"先查文献 → 再读 → 再设计实验 → 再写 → 再降重"这种多阶段。
   每一步都需要人介入、改写、再继续。完全自动的 Agent（如 GPT Researcher / OpenHands）跑出来的报告，研究者不能直接用。

Selenyx 的架构就长在这些约束的交叉点上：

### 2.1 引擎层：Harness + Loop + Skills（不是 Chain）

- 整体心智模型抄自 Hermes Agent（219k★）和 LangGraph（37k★）：**Harness 提供统一接口，Loop 把每一次任务
  切成"接收→推理→工具调用→结果回流→中断/继续"**，但**不锁死**任何环节。
- Skills 是可插拔的 Node.js 模块，每个技能都有：
  - **L1（离线确定性算法）**：纯算法跑、零 LLM 调用、可审计、可复现。例：`aigcCheck` 用句长波动+词汇多样性+AI 套话密度
    五维启发式打分；`plagiarism` 用 8 字 shingle 自重复检测；`translate` 的术语库查找。
  - **L2（LLM 增强版）**：当用户配置了大模型 provider，技能自动升级为 LLM 路径，但**硬约束**写在系统提示词里——
    "只依据所给文本"、"事实与引用标记零改动"、"不输出未报告的字段"。
- 这一层解决**约束 1（证据链）**：每个技能都自带保护位逻辑，引用/数值/缩写先 mask 再 translate，输出时再 restore。

### 2.2 记忆层：Scholar Profile（不是向量库）

- 科研场景里，向量库擅长"召回相似的文献"，但"用户更想读什么"是另一件事。
- Selenyx 的 `profile.js` 用**事件折叠**而不是向量：每一次"读了一篇 SBAR 论文"、"给一段批了红"、
  "搜了一次" 都会被加成权重写到 `~/.selenyx/profile.json`（仅本地、纯文本、可清空）。
- 读到第 47 篇时，"SBAR" 已经是权重 34 的兴趣词；下次新文献的相关性评分会自动用它。
- 这一层解决**约束 2（本地敏感）**：profile.json 不上云、不联网同步，文件位置用户可改、可清空。

### 2.3 UI 层：Hermes 布局 + 阅读模式 + 内置浏览器

- 抄自 Hermes Desktop 的三栏：左侧"新建对话 / 项目 / 会话 / 产物 / 技能"、中央聊天/阅读/浏览器、右栏"任务板 + 拉取文档 + 批注"。
- 抄自小绿鲸的五色批注语义：红=关键/风险、黄=重点、绿=可借鉴、蓝=待查证、紫=与我相关。
- 内置 WebContentsView（Electron）让用户**一边让 agent 后台翻译 6 段文献，一边自己刷 bilibili**——研究本来就是这种节奏。
- 这一层解决**约束 3（长链路协作）**：每一步都看得到、改得了、查得到产物。

## 三、为什么选 Electron 而不是 Tauri / Flutter / 纯 Web

- Tauri 包体小，但要写 Rust 桥，重写技能层；研究场景用 WebContentsView 内置浏览器、Chromium PDF 渲染是刚需。
- Flutter 桌面与 Web 生态（PDF.js、MathJax、ECharts、视频）桥接成本太高。
- 纯 Web 不能装本地引擎、上传本地 PDF、跑本地 LLM。
- Electron 让 Selenyx 核心（纯 Node.js）能**直接当 Electron 主进程的子模块 import 进来**——零语言边界。
  同一份 `src/skills/aigcCheck.js` 既能在 CLI 跑，也能在桌面端跑，121/121 测试一次跑通。

## 四、别人为什么要换过来（Selenyx 的差异化）

| 你现在 | 痛点 | 切到 Selenyx 之后 |
|---|---|---|
| 知网检索 + 单独翻译软件 + 单独 AIGC 检测 + 单独降重 | 7 个软件切换、产物不互联 | 一次对话拉通全链路，产物自动进面板 |
| ChatGPT 帮写 → 改 → 检测 → 改改改 | 数据上传海外、引用标错、术语不统一 | 全部本地、术语库保护、引用零污染 |
| Zotero 读文献 + Notion 做笔记 + 备忘录写心得 | 读完一遍手抄批注，搜不回 | 五色批注 + Markdown 导出 + 相关性评分 |
| Cursor / Claude Code 写代码 | 不是研究场景 | Selenyx 是研究副驾驶，写代码只是技能之一 |

## 五、Selenyx 的「明确拒绝」

为了让大家知道我们在哪里有取舍：

- **不会越来越"AI 化"**——月相主题是为了让科研场景安静，不是炫技。技能输出永远有"硬约束 + 免责声明"，
  L1 跑不出结果时不强行用 LLM 凑。
- **不会偷偷联网**——联网是显式动作（聊天里说"帮我查"），不是默认行为。所有联网动作进任务板，可追溯。
- **不会做"自动出报告"**——每一步留给你改。`summarize` 标注"文中未报告"的字段；`humanize` 标记每一处改动；
  `aigc-check` 给到句级别证据。
- **不会绑云**——所有 L1 离线可跑；接云是用户主动配的 API Key，不内置任何默认云服务。
- **不会替你做决定**——批注五色由你选，翻译术语由你定，相关性阈值由你设。

## 六、用 Selenyx 的几个具体姿势

1. **查文献**：「帮我查 SBAR 交接训练对护生临床推理的最新证据」→ 联网检索知网 + PubMed → 文献拉到右栏 → 点开进阅读模式。
2. **读文献**：选中一段，点紫色批注（与我相关）→ 右栏出现「相关性 86% · 命中画像中 5 个高权重主题」→ 一键翻译/总结。
3. **写报告**：把可研报告粘贴到对话框 → 「AIGC 率检测并降重」→ 检测报告 + 降重后版本都进产物面板。
4. **刷剧+研究**：内置浏览器打开 bilibili，agent 在后台翻译刚拉到的 PDF，进度条在右栏可见。

## 七、对未来的承诺

- **本地优先**：默认本地网关、本地 LLM、本地 profile。新功能上线前问自己"必须联网吗"。
- **研究优先**：场景永远先想"科研用得到吗"，再想"普通用户呢"。
- **可审计**：每个技能输出有证据，修改有 diff，决策有迹可循。
- **可拒绝**：伦理边界硬编码——`humanize` 只用于自己原创内容的表达自然化；`aigc-check` 必须给免责声明。
- **可接入**：MCP / 自定义 skill / 自定义 LLM 接入路径，2026 H2 完成。
